# Figma → セクション実装

引数: `$ARGUMENTS`

## 1. デザインを読む

- Figma MCP の `get_design_context` で対象ノードの構造・値を取得し、`get_screenshot` で見た目を確認する
- SP と PC のフレームが別にあれば両方読む。片方しかなければ、もう片方の挙動をユーザーに確認する（推測で決めない）
- 実装先が指定されていなければ、どの `page-*.php` に入れるか聞く

## 2. トークンに当てはめる（ここが最重要）

- 色・フォントサイズ・ウェイト・行間を `sass/abstracts/_variables.scss` の既存トークンに当てはめた**対応表**を作る
- 近い値（±1〜2px、ほぼ同じ色）は既存トークンに寄せる
- 本当に新しい値だけ、**用途名**でトークンを追加する（例: `$color-bg-recruit`）。3 つ以上追加しそうなら実装前にユーザーに確認する
- 余白は 8 の倍数に丸めてよいか、デザインの値をそのまま使うかを最初に決める（既定は丸める）

## 3. 構造を決める

- セクションのブロック名: `{page}{Section}`（例: `recruitMessage`）
- 他ページにも出てくる要素（見出し・ボタン・カード）は、既存の `template-parts/` と `sass/components/` を先に探して使い回す
- 見出しの階層: セクションは `h2`、その中は `h3`
- 画像は `img/{page}/` に WebP で書き出す（Figma MCP でダウンロードできない場合は、必要な画像のファイル名一覧をユーザーに渡す）。`width` / `height` 属性を付ける

## 4. 実装

- SP ファーストで書き、`mq(md)` / `mq(lg)` で広げる
- 動きの指定があれば `fade-in-*` / `crop-from-*` を付ける
- 装飾だけの画像は `alt=""`、意味のある画像は内容を `alt` に書く

## 5. 確認

- hooks のビルド・lint が通っていること
- ブラウザで 375px と 1280px を開き、Figma のスクリーンショットと見比べる。ずれがあれば直す
- 最後に「トークン対応表」と「デザインと変えた点（丸めた余白など）」を報告する
